## 2. 对项目的影响

- 已按新需求补上 OCR：`OCR_ENABLE=true` 时，无文字层的 PDF 自动走
  `rapidocr`（文字）+ `pix2tex`（独立公式→LaTeX），状态机会先进入 `stage=ocr`。
- 关闭 OCR（`OCR_ENABLE=false`）时仍按原逻辑抛 `2003` 并标 `rejected`。
- CPU 实测约 3–5 秒/页，884 页全量约 45–75 分钟；建议先用 `--pages` 做小样。

## 3. 三条可选路径

| 方案 | 做法 | 时间（884 页） | 公式质量 | 额外成本 |
|---|---|---|---|---|
| **A. 离线 OCR 预处理（已落地）** | `scripts/ocr_pdf.py`：rapidocr 识文字 + pix2tex 转公式 | CPU 45–75 分钟 | 文字好；**独立公式好，行内公式仍是原文** | 已装 rapidocr / pix2tex |
| **B. 商业公式 OCR** | Mathpix / 腾讯云 / 百度公式识别，按页计费 | 1–2 小时 | 好 | 约 ¥50–300（按 0.05–0.3 元/页） |
| **C. 换数据** | 找出版社数字版、学校讲义、或自己录入的题 | 取决于来源 | 最好 | 0 |

**不建议**：直接把扫描件塞进流程再"假装成功"。没有文字层，检索必然全空。

## 4. 建议的执行顺序

1. **先做 10 页小样**：每本挑 3 页（含公式、含例题），用 A/B 两种方案各跑一次，人工看公式还原是否可用。
2. 小样合格 → 再决定全量；不合格 → 只 OCR"例题页"（预计 150–200 页，成本降 70%）。
3. OCR 产物落到 `knowledge/raw/kaoyan_math1/<书名>/`，先 `--dry-run` 体检，再入库。
4. 原始扫描件与 OCR 产物都**不进公开仓库**（版权 + 体积）。

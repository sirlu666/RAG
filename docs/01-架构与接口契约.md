## 1. 分层架构

```
┌─────────────────────────── Browser (Vue3 + Vite) ───────────────────────────┐
│  views/        ChatView / KbView / DocView / LoginView                      │
│  components/   MarkdownRenderer(KaTeX) / CitationCard / DocUploader         │
│  api/          http.ts(axios 拦截器) / sse.ts(fetch + ReadableStream)       │
└──────────────────────────────────┬──────────────────────────────────────────┘
                                   │ HTTP / SSE
┌──────────────────────────────────┴──────────────────────────────────────────┐
│                         FastAPI (backend/app)                                │
│  api/         auth.py  kb.py  doc.py  chat.py                               │
│  services/    auth_service  doc_service(任务状态机)  kb_service             │
│  rag/         splitter(A)  embedder  retriever(B)  reranker  pipeline(B)    │
│               prompt(B)  context  evaluator                                  │
│  db/          models.py  session.py                                          │
│  core/        config  security(JWT)  logging  exceptions  deps              │
└───────┬───────────────────────┬──────────────────────┬───────────────────────┘
        │                       │                      │
   SQLite(WAL)/PG          Chroma(persist)        DeepSeek API
   (元数据/消息)           (向量+metadata)        (chat/completions, stream)
```

**分层铁律**
- `api/` 只做：参数校验 → 调 service → 组装 `ApiResponse`。不写业务逻辑，不直接碰 Chroma。
- `rag/` 是纯函数/纯类，**不 import FastAPI**，可被 `scripts/` 复用（评估要用）。
- 依赖单向：`services` 可调 `rag`，`rag` 不可调 `services`。

## 2. 数据模型（SQLAlchemy 草案）

```python
# users                        # 个性化已砍：无 theme / font_size / avatar
id, username(unique), email(unique), password_hash, nickname, role('user'|'admin'), created_at

# knowledge_bases
id, user_id(FK), name, description, subject, is_public(bool), created_at
# 唯一约束 (user_id, name)；is_public 仅管理员可置 True

# documents
id, kb_id(FK), user_id, filename, stored_path, file_type('pdf|docx|md|txt'),
size_bytes, page_count, status('pending|parsing|embedding|ready|failed|rejected'),
error_msg, chunk_count, content_hash(sha256), created_at, updated_at

# chunks                       # 关系库存权威正文，Chroma 存向量
id, doc_id(FK), kb_id, user_id, seq(int), content(text),
content_type('concept|example|exercise|theory|other'),
page(int|None), char_start, char_end, token_count, vector_id(str), created_at

# conversations
id, user_id, kb_ids(json), title(首问截断), created_at, updated_at

# messages                     # 无 image_url；无 feedback 表
id, conversation_id(FK), role('user|assistant'), content(text),
citations(json: [{chunk_id, doc_id, doc_name, page, snippet, score}]),
tokens_in, tokens_out, latency_ms, first_token_ms, model, created_at

# ingest_tasks
id, doc_id, status, progress(0-100), stage('parse|split|embed|index'), error_msg,
started_at, finished_at

# eval_runs                    # 答辩要用的可复现记录
id, name, dataset, recall_at_5, mrr, answer_acc, avg_latency_ms, config(json), created_at
```

索引：`chunks(doc_id)`、`chunks(kb_id)`、`messages(conversation_id)`、`documents(content_hash)`、`documents(kb_id, status)`。

**删除语义（目标 4 的验收点）**
删文档 = 软删记录 → 删向量（`where={"doc_id": id}`）→ 删原文件 → 消息里的 citation 标为"来源已删除"。
删库 = 同上批量执行 + 删 messages 的会话引用（会话保留，引用降级）。

## 3. ChunkMetadata 契约（A → B 交接面 · 冻结）

Chroma 记录：`id = chunk.id`，`document = chunk.content`，`embedding = vector`。
`metadata` 只能是下表的子集（Chroma 仅支持 str/int/float/bool，禁止嵌套）：

| key | 类型 | 必填 | 说明 | 谁写 | 谁读 |
|---|---|---|---|---|---|
| `chunk_id` | str | ✅ | 与关系库 `chunks.id` 一致 | A | B/C |
| `user_id` | str | ✅ | 隔离兜底；公共库为 `public` | A | B |
| `kb_id` | str | ✅ | 知识库 ID | A | B |
| `doc_id` | str | ✅ | 文档 ID | A | B |
| `doc_name` | str | ✅ | 展示用文件名 | A | C |
| `subject` | str | ✅ | `highschool_math` / `calculus` | A | B |
| `content_type` | str | ✅ | `concept\|example\|exercise\|theory\|other` | A | B/C |
| `page` | int | ❌ | PDF 页码，从 1 开始 | A | C |
| `seq` | int | ✅ | 文档内顺序号（前后文扩展用） | A | B |
| `has_formula` | bool | ✅ | 含 LaTeX 则为 True | A | B |

> 已删除字段：`kp_ids`、`difficulty`、`grade`（依赖自动打标签，见 06 §2）。

**过滤与越权（必须照抄）**

```python
# 1) 先校验归属，再检索。kb_ids 来自请求体，绝不可直接信任
readable = kb_service.assert_readable(user_id, kb_ids)   # 越权 → AppError(1003)
# 2) 只在这个白名单内过滤
where = {"$and": [{"kb_id": {"$in": readable}}, {"subject": subject}]}
# 3) 删文档必须整批删，禁止逐条
collection.delete(where={"doc_id": doc_id})
```

## 4. 切片规格（A 的自检标准）

| 项 | 规格 |
|---|---|
| 目标长度 | 400–800 tokens（中文约 300–600 字） |
| 上限 | 1000 tokens，超限在段落边界强制切 |
| overlap | 80–120 tokens，仅在被迫切断时使用 |
| 公式保护 | 切点不得落在 `$...$` / `$$...$$` / `\begin{}...\end{}` 内部 |
| 单元完整性 | 例题的"题干 + 解析 + 答案"同 chunk（超长则题干单独成块并标 `split_of`） |
| 断行修复 | 中文行尾无标点且下一行非编号 → 合并 |
| 噪声 | 页眉/页脚/页码：出现率 > 60% 的重复行判为噪声 |
| 拒收 | 每页有效字符 < 50 → `documents.status=rejected`，不做 OCR |

## 6. SSE 协议（`POST /api/chat/stream`）

**请求**（无 `image_url`，无停止接口）

```json
{ "conversation_id": "c_123|null", "kb_ids": ["kb_1"], "question": "...", "stream": true }
```

**响应** `text/event-stream`，事件顺序固定：

```
event: meta
data: {"message_id":"m_1","conversation_id":"c_1","retrieval_ms":210,"hits":5}

event: citation
data: {"index":1,"chunk_id":"ch_88","doc_name":"人教A版必修一.pdf","page":132,"snippet":"...","score":0.83}
   （可多次，先于正文，前端先渲染来源卡片骨架）

event: delta
data: {"text":"由题意，"}

event: done
data: {"message_id":"m_1","tokens_in":1820,"tokens_out":640,"latency_ms":5200,"confidence":0.81}

event: error
data: {"code":4001,"message":"模型服务繁忙，请稍后重试"}
```

**类型化要求（新增，防"字段改名无报错"）**
- `app/api/schemas.py` 定义 `MetaEvent / CitationEvent / DeltaEvent / DoneEvent / ErrorEvent`。
- 契约测试：读 `docs/api/mock/chat_stream.txt` → 逐帧 `model_validate` → 断言字段齐全。mock 即"可执行契约"。

**前端实现要点**
- 用 `fetch` + `ReadableStream`（`EventSource` 不支持 POST + Header），按 `\n\n` 分帧，`data:` 多行需拼接。
- `delta` 累积到 buffer，`requestAnimationFrame` 每帧 flush，避免逐字重排。
- 无停止按钮：中断只做"重新生成"（前端 abort 后重发，旧消息标 `cancelled` 或不落库）。

## 7. 上传任务状态机

```
pending ──> parsing ──> embedding ──(索引完成)──> ready
   │            │            │
   └────────────┴────────────┴──(异常)──> failed（可重试 → pending）
                              └──(无文本层)──> rejected（不可重试，需换文件）
```

- `progress`：parse 0-40、split 40-60、embed 60-95、index 95-100。
- 同一时刻只允许 1 个入库任务（DB 标记），其余进队列，前端显示"排队中"。
- 前端每 1.5s 轮询 `#9`；`failed` 显示错误与"重试"，`rejected` 显示"请上传文字版"。

## 8. 契约工作流

1. B 先写 Pydantic schema，FastAPI 自动生成 `/openapi.json`。
2. C 用 `pnpm gen:types`（openapi-typescript）生成类型，字段名不靠猜。
3. 后端未就绪时，C 用 `docs/api/mock/*.json` + MSW 起 mock。
4. 契约变更：改 schema → 群里 @ 对方 → 更新本文件 → 当天对齐。
5. 每个接口 DoD：有 schema、有 1 条 pytest、有 `/docs` 示例；**检索类接口必须有一条越权测试**。

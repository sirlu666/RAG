# 01 · 架构与接口契约

> **本文件是三人组的"宪法"**。§3 的 ChunkMetadata 与 §5 的 API 清单一旦冻结，任何修改必须在群里说明 + 更新版本号。

## 1. 分层架构

```
┌─────────────────────────── Browser (Vue3 + Vite) ───────────────────────────┐
│  views/        ChatView / KbView / DocView / LoginView / SettingView        │
│  components/   ChatBubble(SVG-Stream) / MarkdownRenderer(KaTeX) / Uploader  │
│  api/          http.ts(axios 拦截器) / sse.ts(fetch + ReadableStream)       │
└──────────────────────────────────┬──────────────────────────────────────────┘
                                   │ HTTP / SSE
┌──────────────────────────────────┴──────────────────────────────────────────┐
│                         FastAPI (backend/app)                                │
│  api/         auth.py  kb.py  doc.py  chat.py  feedback.py                   │
│  services/    auth_service  doc_service(任务状态机)  kb_service              │
│  rag/         splitter(A)  embedder  retriever(B)  reranker  pipeline(B)     │
│               prompt(B)  memory  evaluator                                   │
│  db/          models.py  session.py  migrations                              │
│  core/        config  security(JWT)  logging  exceptions  deps              │
└───────┬───────────────────────┬──────────────────────┬───────────────────────┘
        │                       │                      │
   SQLite/PG              Chroma(persist)        DeepSeek API
   (元数据/消息)           (向量+metadata)        (chat/completions, stream)
```

**分层铁律**
- `api/` 只做：参数校验 → 调 service → 组装 `ApiResponse`。**不写业务逻辑，不直接碰 Chroma。**
- `rag/` 只做纯函数或纯类，**不 import FastAPI**，可被 `scripts/` 直接复用（离线评估要用）。
- 跨层禁止反向依赖：`services` 可以调 `rag`，`rag` 不能调 `services`。

## 3. ChunkMetadata 契约（**A → B 交接面 · 冻结**）

Chroma 中每条记录的 `id = chunk.id`，`document = chunk.content`，`embedding = vector`，
`metadata` 必须是下面这张表的**子集**（Chroma 只支持 str/int/float/bool，禁止嵌套 dict/list）：

| key | 类型 | 必填 | 说明 | 谁写 | 谁读 |
|---|---|---|---|---|---|
| `chunk_id` | str | ✅ | 与关系库 `chunks.id` 一致 | A | B/C |
| `user_id` | str | ✅ | 隔离依据；公共库用 `public` | A | B |
| `kb_id` | str | ✅ | 知识库 ID | A | B |
| `doc_id` | str | ✅ | 文档 ID | A | B |
| `doc_name` | str | ✅ | 展示用文件名 | A | C |
| `subject` | str | ✅ | `highschool_math` / `calculus` / `linear_algebra` | A | B |
| `grade` | str | ❌ | `高一`/`高二`/`大一`… | A | C |
| `content_type` | str | ✅ | `concept\|example\|exercise\|theory\|other` | A | B/C |
| `kp_ids` | str | ❌ | 知识点 ID，多个用 `,` 连接（如 `derivative,chain_rule`） | A | B |
| `difficulty` | int | ❌ | 1-5 | A | C |
| `page` | int | ❌ | PDF 页码，从 1 开始 | A | C |
| `seq` | int | ✅ | 文档内顺序号，用于"前后文扩展" | A | B |
| `has_formula` | bool | ✅ | 含 LaTeX 则为 True（检索加权 + 前端提示） | A | B |

**附加约定**
- `where` 过滤模板（B 直接用）：
  ```python
  where = {"$and": [{"kb_id": {"$in": kb_ids}}, {"subject": subject}]}
  # 公共库：kb_id = "public"
  ```
- 同一 `doc_id` 的 chunk 删除必须走 `collection.delete(where={"doc_id": doc_id})`，禁止逐条删（易漏）。
- `content` 内公式统一为 **`$...$`（行内）/ `$$...$$`（块级）**，禁止 `\(...\)` 与 `\[...\]`（前端统一转换，后端统一输出）。

## 4. 切片规格（A 的自检标准）

| 项 | 规格 |
|---|---|
| 目标长度 | 400–800 tokens（中文约 300–600 字） |
| 上限 | 1000 tokens，超限强制在段落边界切 |
| overlap | 80–120 tokens，仅在被迫切断时使用 |
| 公式保护 | 切分点不得落在 `$...$` / `$$...$$` / `\begin{...}...\end{...}` 内部 |
| 单元完整性 | 例题的"题干 + 解析 + 答案"必须同 chunk（超长则题干单独成 chunk 并在 `meta` 里标 `split_of`） |
| 断行修复 | PDF 解析后合并硬换行（中文行尾无标点且下一行非编号 → 合并） |
| 噪声 | 去页眉页脚/页码/水印（正则 + 重复行统计，出现率 > 60% 的行判为页眉页脚） |

### 错误码

| code | HTTP | 含义 |
|---|---|---|
| 0 | 200 | 成功 |
| 1001 | 400 | 参数校验失败 |
| 1002 | 401 | 未登录 / token 过期 |

## 6. SSE 协议（`POST /api/chat/stream`）

**请求**
```json
{ "conversation_id": "c_123|null", "kb_ids": ["kb_1","public"], "question": "...", "image_url": null, "stream": true }
```

**响应** `Content-Type: text/event-stream`，事件序列固定：

```
event: meta
data: {"message_id":"m_1","conversation_id":"c_1","retrieval_ms":210,"hits":5}

event: citation
data: {"index":1,"chunk_id":"ch_88","doc_name":"人教A版必修一.pdf","page":132,"snippet":"...","score":0.83}
   （可多次，先于正文推送，前端先渲染"参考来源"卡片骨架）

event: delta
data: {"text":"由题意，"}

event: delta
data: {"text":"设 $f(x)=x^2+2x$，则 ..."}

event: done
data: {"message_id":"m_1","tokens_in":1820,"tokens_out":640,"latency_ms":5200,"confidence":0.81}

event: error
data: {"code":4001,"message":"模型服务繁忙，请稍后重试"}
```

**前端实现要点（C）**
- 用 `fetch` + `ReadableStream` 手解析 SSE（`EventSource` 不支持 POST + Header）。
- 必须按 `\n\n` 分帧，`data:` 可能多行拼接；收到 `done`/`error` 才关闭连接。
- 渲染节流：`delta` 累积到 buffer，`requestAnimationFrame` 每帧 flush 一次（避免每个字符重排）。
- Mock：`docs/api/README.md` 的 `mock/chat_stream.txt` 可直接喂给同一个解析器，无后端也能联调。

## 7. 上传任务状态机

```
pending ──(开始)──> parsing ──(切分)──> embedding ──(索引完成)──> ready
   │                   │                  │
   └───────────────────┴──────────────────┴──(异常)──> failed(可重试 → pending)
```

- `progress`：parse 0-40、split 40-60、embed 60-95、index 95-100。
- 前端：上传后每 1.5s 轮询 `#10`，进度条 + 阶段文案；`failed` 显示 `error_msg` 与"重试"按钮。

## 8. 契约的工作流（怎么用才不吵架）

1. B 先写 Pydantic schema（`app/api/schemas.py`），FastAPI 自动生成 `/openapi.json`。
2. C 用 `openapi-typescript http://127.0.0.1:8000/openapi.json -o src/api/schema.d.ts` 生成类型，**字段名不用猜**。
3. 后端未就绪时，C 用 `docs/api/mock/*.json` + MSW 起 mock，页面照常开发。
4. 契约变更流程：改 schema → 群里 @对方 → 更新本文件 §5 → 双方当天对齐。
5. 每个接口的 DoD：有 Pydantic schema、有 1 条 pytest 用例、有 `/docs` 里的示例。

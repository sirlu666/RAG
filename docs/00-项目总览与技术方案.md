# 00 · 项目总览与技术方案（v2.1）

> v2.1 按「非目标全部砍掉」收缩范围：拍照/OCR、相似题、自动标签、个性化、匿名提问、反馈、指代改写全部移除。
> 范围准据见 `06-范围基线.md`；本文件只解释"为什么这样做"。

## 1. 目标（四条，都要能量化验收）

| # | 目标 | 验收口径 | 复现方式 |
|---|---|---|---|
| 1 | **有据可查** | 每条回答带引用片段；引用能定位到文档 + 页码；点开可高亮原文 | 人工抽 20 条，引用可跳转率 100% |
| 2 | **答得对** | Recall@5 ≥ 0.85；答案正确率 ≥ 0.80 | `python scripts/eval.py --dataset eval/math_80.jsonl`（80 题，temperature=0，跑 3 次取均值） |
| 3 | **数学友好** | 公式在切片/检索/生成/展示四步不被破坏 | 单测 1000 次切片无公式截断；10 个刁钻样例渲染通过 |
| 4 | **可运营** | 自建库、增量更新、删除后检索无残留 | 删除后断言 `collection.get(where={"doc_id": id})` 为空 |

**四条之外的，一律不做。** 判据：删掉它，哪条指标会下降？答不出就砍。

## 2. 非目标（明确不做，不是"以后再说"）

| 不做 | 一句话理由 |
|---|---|
| 拍照提问 / OCR（含扫描件、公式识别） | 不改善任何一条指标；公式识别错会污染答案；成本 ~35h |
| 相似题推荐 | 教学增值，与"答得对"无关 |
| 自动打标签（知识点/难度） | 标签只服务于筛选，而筛选不是目标 |
| 个性化（头像/主题/字号） | 纯装饰 |
| 未登录提问 / 匿名限流 | 可运营要求"有账号"；匿名让每个页面多一套分支 |
| 点赞点踩 | 无消费方，数据无用 |
| 多轮指代消解 / LLM query 改写 | 只保留"近 3 轮上下文"（成本 8h vs 18h） |
| 微调、Agent 工具链、多模态生成、移动端 | 成本高、与可溯源目标正交 |
| 教师端 / 班级 / 权限矩阵 / 收藏 | 单用户模型扩成多租户，工作量翻倍 |

> 这些不是"被删掉的遗憾"，而是**答辩时的局限章节**：每条写一句"为什么这次不做、以后怎么做"。

## 3. 用户与场景（只剩两条主链路）

- **学生**：登录 → 建知识库 → 上传教材/讲义 → 提问 → 看分步解答 + 引用 → 跳到原文 → 追问（同会话 3 轮内）。
- **管理员（就是你）**：批量入库 `knowledge/raw/` → 看评估报告 → 调切片与检索参数。

没有访客态、没有分享、没有协作。

## 4. 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 前端 | Vue 3 + Vite + TS + Element Plus + Pinia | 生态熟、组件全 |
| 公式 | **KaTeX** | 同步渲染、快；比 MathJax 轻 |
| Markdown | markdown-it + highlight.js | 插件链可控，能拦公式做占位符保护 |
| 流式 | **SSE**（fetch + ReadableStream） | 单向下行足够；Nginx 只需关 buffering；比 WebSocket 好调 |
| 后端 | FastAPI + Pydantic v2 | 自动 OpenAPI，直接当契约 |
| DB | SQLite（WAL）→ PostgreSQL | 开发零配置；上线只改连接串 |
| 向量库 | Chroma（PersistentClient，单 collection + metadata） | 零运维、支持 where 过滤 |
| 检索 | BM25（jieba）+ 向量 → RRF → Rerank | 符号精确匹配 + 语义泛化互补 |
| Embedding | bge-m3 | 中英混合、数学术语表现好 |
| Rerank | bge-reranker-v2-m3 | Top-20 → Top-5 提升明显 |
| 大模型 | DeepSeek-chat（OpenAI 兼容、流式） | 中文强、便宜、无需自建显卡 |
| 解析 | PyMuPDF（文本层）+ python-docx + markdown-it-py | 只做文本层，扫描件直接拒收 |
| 部署 | Docker Compose + Nginx | 一台机器、可离线演示 |

**没有的依赖**：PaddleOCR、MinerU、pix2tex、Mathpix、Celery、Redis、Milvus。一个都不装。

## 5. 两条链路

### 5.1 入库

```
上传 → 落盘 → documents(status=pending)
  → BackgroundTasks：解析（文本层）→ 清洗（页眉页脚/硬换行）
  → 结构化识别（知识点/例题/习题）→ 公式保护切片
  → 批量 embedding → 写 Chroma + chunks 表 → status=ready
失败 → failed + error_msg（前端可重试）
无文本层 PDF → 直接拒绝「该文档没有文字层，请上传文字版」（不做 OCR）
```

### 5.2 问答

```
提问 → （同会话则附最近 3 轮）→ 并行 BM25 Top-20 / 向量 Top-20（kb 归属已校验）
  → RRF 融合 → Rerank → Top-5
  → 最高分 < 阈值 → 走"未找到依据"兜底
  → Prompt（System + Few-shot + 片段 + 历史 + 问题）→ DeepSeek 流式
  → SSE：citation（先）→ delta（流）→ done（token/耗时/置信度）
  → 落库 messages（含 citations JSON）
```

## 6. 关键决策

| ADR | 决策 | 理由 |
|---|---|---|
| 01 | 单 collection + metadata 过滤 | collection 随文档膨胀后管理成本失控；Chroma where 够用（chunk ≤ 1 万） |
| 02 | 按"知识点—例题—习题"结构化切片，公式用占位符保护 | 数学的最小语义单元是一道完整例题；切断题干与解答会导致检索命中但生成错乱 |
| 03 | BM25 + 向量 → RRF → Rerank | 题干常含精确符号（BM25 强）；"求导"≈"导数计算"（向量强）；RRF 免归一化 |
| 04 | 流式用 SSE | 不需要双工；断线可重连；Nginx 一行配置。代价：不支持中途打断——所以**不做停止按钮** |
| 05 | 解析用 BackgroundTasks + 状态机 | 单机低并发足够；接口按"可抽到 RQ"设计，未来不改契约 |
| 06 | 检索不到就拒答 | 数学编造代价高；阈值 + 强制引用 + `[n]` 后置校验三层 |
| 07 | 只收文本层 PDF | 扫描件识别准确率不可控，宁可拒收并给明确提示 |

## 7. 降级与容错

| 故障 | 表现 | 降级动作 |
|---|---|---|
| DeepSeek 超时/限流 | 首 token > 10s | 退避重试 2 次 → 返回"服务繁忙"，不静默失败 |
| Embedding 不可用 | 入库卡住 | 任务标 `degraded` 并提示；不允许"假装成功" |
| PDF 无文本层 | 解析出 < 50 字/页 | 拒绝入库 + 明确文案（不做 OCR 兜底） |
| Chroma 文件损坏 | 检索报错 | `scripts/rebuild_index.py` 从 chunks 表重建 |
| SQLite 写锁 | `database is locked` | WAL + timeout=30 + 单写入者（同一时刻只允许 1 个入库任务） |
| SSE 断流 | 消息中断 | 前端重连 + "重新生成"（不做停止生成） |

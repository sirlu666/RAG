# 02 · 开发流程与里程碑（三人组 · 10 周）

> 总原则：**先纵向打通一条最窄的端到端链路，再横向加宽能力**。
> 反例（也是三人组最容易翻车的方式）：三人各写各的模块，第 8 周才开始联调。

## 0. 阶段总览

| 阶段 | 周次 | 主题 | 一句话目标 | 里程碑（可演示） |
|---|---|---|---|---|
| **P0** | W1 | 需求与契约冻结 | 三个人对同一份接口和数据结构达成一致 | `/docs` 里能看到全部接口；前端用 mock 能点通对话页 |
| **P1** | W2–W3 | 垂直切片 MVP | 上传一份 md → 提问 → 有引用地回答（不流式、纯向量） | 端到端 Demo 跑通，3 人各自环境都能复现 |
| **P2** | W4–W6 | 能力补齐 | PDF/OCR、混合召回、流式、多轮、知识库 CRUD | 真实教材入库，Top-5 命中率可测 |
| **P3** | W7–W8 | 体验与评估 | 有指标、有相似题、有原文跳转、好看的 UI | 评估报告第一版；Demo 视频脚本定稿 |
| **P4** | W9–W10 | 加固与交付 | 稳定、能部署、能答辩 | 一键部署成功；答辩 PPT + 演示视频 |

**阶段门（Gate）**：每个阶段最后一天必须满足 DoD，否则不进入下一阶段 —— 宁可砍功能，不带着坑往前走。

## 1. P0 · W1 需求与契约冻结

| 天 | 全员 | A | B | C |
|---|---|---|---|---|
| D1 | 定学科范围（高中+高数）、定 3 个必做亮点 | 收集语料（教材 2 本 + 讲义 1 份） | 跑通 DeepSeek hello world | 起 Vue 脚手架 + Element Plus |
| D2 | 过 `docs/01` 逐条确认 | 取样 20 页 PDF，试 PyMuPDF 解析质量 | 定 ChunkMetadata 字段（与 A 对齐） | 登录页 UI 骨架 |
| D3 | **冻结契约 v1.0**（打 tag `contract-v1`） | 写 `splitter.py` 原型，跑 1 篇文档看切片 | 写 `schemas.py` + `/chat/stream` 骨架（返回假数据） | 用 mock 打通对话页 + SSE 解析器 |
| D4 | 仓库/CI/环境统一 | 语料清洗脚本 v1 | Chroma 建库 + 嵌入跑通 100 条 | Markdown+KaTeX 渲染组件 |
| D5 | **Gate 0**：全员演示各自跑通的部分 | 汇报切片效果 | 汇报 pipeline 骨架 | 汇报 mock 联调成功 |

**Gate 0 验收**：`git clone` 后按 README 两条命令能跑起来；`/docs` 接口全；对话页能流式打印假回答。

## 2. P1 · W2–W3 垂直切片 MVP

**范围刻意压窄**：只支持 `md/txt`；只有一个公共知识库；纯向量召回；不管权限细节；不美化 UI。

| 周 | A | B | C | 集成点 |
|---|---|---|---|---|
| W2 | 解析器（md/txt/docx）→ 切片器 v2（结构化）→ 批量入库脚本 | pipeline：embed → chroma query → prompt → DeepSeek（非流式） | 上传组件（真实接口）→ 文档列表 → 会话页 | W2 周五：A 的 50 个 chunk 能被 B 检索到 |
| W3 | 去重（content_hash）、删除重建索引 | 接 SSE 流式、引用片段返回 | 流式渲染 + 引用卡片 + 打字机效果 | W3 周五：**端到端 Demo**（上传 md → 提问 → 有引用） |

**Gate 1 验收（硬指标）**
- 上传 5 篇 md，20 个问题中 ≥ 14 个能检索到正确片段（人工判定）。
- 首 token < 3s，完整回答 < 20s。
- 三个人的机器上走同一份 README 都能跑（消除"只有我这儿能跑"）。

## 3. P2 · W4–W6 能力补齐

| 周 | 重点 | A | B | C |
|---|---|---|---|---|
| W4 | 真实 PDF | PyMuPDF 文本层解析、页眉页脚清洗、页码映射、表格降级为文本 | 混合召回（BM25 + 向量 + RRF）、metadata 过滤 | 知识库 CRUD 页、文档预览页（分页看 chunk） |
| W5 | 公式与 OCR | 公式检测与保护、扫描件走 OCR（PaddleOCR + LaTeX-OCR 或 MinerU）、`/chat/ocr` | Rerank 接入、置信度阈值与拒答策略、多轮 query 改写 | 图片上传 + 识别结果可编辑确认、JWT 全链路 |
| W6 | 质量与并发 | 增量更新、`/docs/{id}/reindex`、任务状态机与进度 | Few-shot 模板 3 套（方程/函数图像/证明）、Token 统计与重试 | 会话历史持久化、异常态（失败重试/空态/断流） |

**Gate 2 验收**
- 两本真实教材入库（≥ 800 chunk），Top-5 命中率 ≥ 0.8。
- 扫描版 PDF 能识别（哪怕速度慢），识别出的公式能被 KaTeX 渲染。
- 未登录 → 登录 → 建库 → 上传 → 提问 → 看历史，全流程无断点。

## 7. 测试策略（三个人没有 QA，就靠自动化兜底）

| 层 | 工具 | 覆盖什么 | 谁写 |
|---|---|---|---|
| 单元 | pytest | 切片边界（公式不被切断）、BM25 打分、prompt 拼装、JWT | A/B |
| 接口 | pytest + httpx | 21 个接口的 happy path + 3 个异常分支 | 各自写自己的 |
| 前端 | vitest（可选） | SSE 帧解析器、Markdown/KaTeX 渲染 | C |
| 冒烟 | `scripts/smoke.py` | 上传→等 ready→提问→断言有 citations | C 维护，全员跑 |
| 评估 | `scripts/eval.py` | Recall@5 / MRR / 正确率 | B |

> 只要求一条铁律：**改 `rag/` 或 `splitter.py` 必须跑 `scripts/eval.py` 并把指标贴到 PR 里**，否则检索质量会悄悄退化。

## 8. 8 周压缩版（如果学期更短）

按此顺序合并：P0 压到 4 天；P1 与 P2 合并；砍掉"拍照 OCR、自动标签、个性化、相似题"，改为一句话写在"未来工作"。
必保三件：**结构化切片 + 混合召回 + 引用溯源**——这是项目的技术含金点，不能砍。

## 9. 部署流程（P4 落地）

```bash
# 服务器（2C4G 足够）
git pull && cp .env.example .env && vim .env      # 填 key
docker compose -f deploy/docker-compose.yml up -d --build
docker compose logs -f backend                     # 看启动
# 校验
curl localhost/api/health
```

- 数据卷：`./data/chroma`（向量）、`./data/app.db`（SQLite）、`./data/uploads`（原文件）——**备份这三个就够**。
- Nginx：`/api` 反代后端且 `proxy_buffering off`（否则 SSE 会攒包）；静态资源 gzip + 1 年缓存。
- 演示预案：现场网络不通 → 本地 `docker compose up` + 本地小模型/缓存回答。

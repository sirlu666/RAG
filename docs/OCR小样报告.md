# OCR 小样实验报告（30 页）

| 项 | 值 |
|---|---|
| 样本 | 6 本考研 PDF，各取第 5–9 页，共 **30 页** |
| 引擎 | rapidocr（文字）+ pix2tex（公式） |
| 参数 | 200 dpi，CPU 单进程，公式模式 `pix2tex` |
| 耗时 | **153 秒**（≈ 5.1 秒/页，含模型加载） |
| 日期 | 2026-10-19 |

## 1. 结果

| 书（代号见体检报告） | 页 | 汉字 | 水印残留 | 公式块 | chunk | 类型 |
|---|---|---|---|---|---|---|
| A 基础讲义（概率） | 5 | 1767 | 1 | 1 | 4 | concept×4 |
| B 复习全书（线代） | 5 | 1214 | 0 | 10 | 5 | concept×5 |
| C 复习全书（高数） | 5 | 1539 | 3 | 9 | 4 | concept×4 |
| D 习题册（概率） | 5 | 232 | 0 | 0 | 6 | concept×2 / exercise×4 |
| E 习题册（线代） | 5 | 112 | 0 | 4 | 6 | concept×3 / exercise×3 |
| F 习题册（数一高数） | 5 | 221 | 0 | 0 | 7 | concept×2 / exercise×5 |
| **合计** | **30** | **5085** | **4** | **24** | **32** | concept 20 / exercise 12 |

平均：**170 汉字/页、0.8 个公式块/页、1.07 个 chunk/页**。

## 2. 质量判断

### 2.1 能做对的

- **中文正文识别可用**：概念、定义、解题步骤基本可读，错字率目测 < 5%；
- **页眉/水印清洗有效**：`微信公众号：一研题本…` 等从 34 行降到 4 行；
- **数字题号能进结构化**：`7. 设 A，B 满足…` 被识别为 `exercise`（12 块），
  说明题库类扫描件可以按"题"切分；
- **独立公式能转 LaTeX**：30 页里 24 块，例如
  `$$\mathbb{P}_{N}^{*}=N(N-1)*\cdots*\left(N-n+1\right)$$`。

### 2.2 做不好的（关键）

**(1) 表格被压成一行。** 复习全书的"考纲要求"表格，OCR 后变成：

```
表示法建立应用问题的函数关系有界性单调性性质了解函数周期性奇偶性复合函数…
```

结构全丢。检索还能命中关键词，但**无法按行/列理解**。

**(2) 矩阵、行列式识别成垃圾 LaTeX。** 线代习题第 5 页：

```
p-
7．已知A，B均为4阶矩阵，r(AAT）)=3，|AB -a -5
$$
-1\ \ \ \ 2\ \ \ \ -5\ \ \ \ 3\ \ \ |\ \ \ |-1\ \ \ 2\ \ \ -5
$$
```

这是 pix2tex 对多行矩阵无能为力的典型表现——比保留原文更糟，属于**伪造 LaTeX**。

**(3) 行内公式仍是原文。** `P(A|B)=1/3` 会变成 `P(A|B)=1/3` 或 `P(BIA)`，
取决于当页清晰度；这类公式占考研题的大头。

**(4) 字符召回有限。** 密集讲义页目测 700–800 字，实际识别 300–380 字/页（召回约 50%），
小字号、上下标、浅色底纹处丢字明显；做题本的低字符数是**真实排版留白**（一页只有 1–2 题），不是漏识别。

## 3. 性能外推

| 规模 | 耗时（单进程 CPU） |
|---|---|
| 30 页 | 2.5 分钟 |
| 300 页（挑重点章节） | 25 分钟 |

## 4. 结论

| 用途 | 是否可用 |
|---|---|
| 关键词检索、定位到"哪一章讲过" | ✅ 可用 |
| 概念/步骤的语义检索 | ⚠️ 勉强（召回约 50%） |
| 公式级问答（求导、矩阵运算、精确符号） | ❌ **不可用** |
| 直接入库作为答辩语料 | ❌ 不建议，需先解决表格与行内公式 |

**不建议直接全量 884 页。** 现在全量跑完，得到的是一批"能搜到关键词、但公式不可信"的 chunk，
反而会在答辩时暴露质量问题。

## 5. 三个可选方案

| 方案 | 做法 | 质量 | 成本 | 建议 |
|---|---|---|---|---|
| **A. 缩小范围** | 只 OCR 3 本讲义/全书的概念+例题章节（约 250–300 页），做题本只取题干 | 与本次小样相同 | 25 分钟 | 应急可用，但公式问题仍在 |
| **B. 上 MinerU** | 版面模型：识别表格、行内公式、阅读顺序 | 明显更好 | 装 1–3GB，跑 2–4 小时 | **预算为 0 时首选** |
| **C. 用 Mathpix** | `OCR_FORMULA=api`，按页计费 | 最好（表格+行内公式） | 884 页约 ¥15–60（按官网单价，量大再谈） | **答辩优先时首选** |

**我的建议**：先花 ¥10 左右用 Mathpix 跑 30 页，和这份报告做对照。
如果公式正确率明显提升，就用 C 全量；如果预算不允许，用 B（MinerU），并接受更长的等待。

## 6. 多模态方案（智谱 glm-4v-plus 实测通过）

`OCR_ENGINE=vlm`：整页图片直接交给视觉语言模型，输出 Markdown（表格/行内公式/阅读顺序一次到位）。

实现：`backend/app/services/parsing/vlm.py`
- 输入：页面渲染图（PNG data URI）+ 固定转录 Prompt（只转录、不改写、无法辨认写 `[不清]`）；
- 输出：Markdown，行内 `$...$`、块级 `$$...$$`、表格 Markdown；
- 门禁：`$`/`$$` 不成对、内容过少 → 打 warning，供人工抽检；
- 失败重试 3 次（429 退避）；未配 key 直接报 `2003`，不会静默降级。

配置：

```bash
OCR_ENGINE=vlm
VLM_API_BASE=https://dashscope.aliyuncs.com/compatible-mode/v1
VLM_API_KEY=sk-xxx
VLM_MODEL=qwen-vl-max
```

| 模型 | 参考成本（884 页） | 说明 |
|---|---|---|
| qwen-vl-plus | ¥15–30 | 性价比路线 |
| qwen-vl-max | ¥35–70 | 复杂版面/公式更稳 |
| glm-4v | ¥20–50 | 备选 |

（单价以各平台官网为准，一页约 1–1.5k 视觉 token + 0.6k 输出。）

### 6.1 A/B 实测（同一批 30 页，2026-10-19，glm-4v-plus）

| 指标 | rapid（逐行 OCR） | vlm（整页转录） |
|---|---|---|
| 耗时 | 153s（5.1s/页） | 396s（13.2s/页） |
| 汉字数 | 5,085 | 4,971 |
| 识别出的例题 chunk | **0** | **6** |
| 识别出的习题 chunk | 12 | **25** |
| 行内公式 | ❌ `P(BIA)` 失真 | ✅ `$r(AA^T)=3$` 正确 |
| 矩阵/行列式 | ❌ 垃圾 LaTeX | ✅ `\begin{vmatrix}` 结构完整 |
| 表格 | ❌ 压成一行 | ✅ Markdown 表格 |
| 例题编号（例 1.1） | ❌ 丢失 | ✅ 保留 |
| 水印行 | 4 | 1 |

结论：**VLM 全面优于 rapid 管线**。此前"不建议全量"的四个问题中三个（表格 / 矩阵 / 行内公式）已解决，
例题识别从 0 到 6，说明结构化质量同步提升。

遗留小问题：
- 少量裸 LaTeX 行缺定界符（不影响主流程，门禁会告警）；
- 模型会自行补标题层级（`## 一、`），原书若无此结构属轻度"美化"，可接受。

全量 884 页：约 13s/页，串行约 3.2 小时；费用按 glm-4v-plus 单价估计在个位数人民币量级
（每页约 2k 视觉 token + 0.8k 输出），以智谱官网账单为准。

**注意**：整页上传第三方 API 等于把扫描内容外发，这几本教辅来源不明，合规上要谨慎；
如果在意，用本地 Qwen2.5-VL 或 MinerU，代价是显存/时间。

# 图片上传与本地文字 OCR

本课先完成静态 PNG/JPG/JPEG 图片进入资料库和问答检索的完整链路。图片经本机 RapidOCR 识别文字，再复用现有切片、向量入库、正文预览和引用流程；不会调用付费公式 OCR 服务。

当前限制：一张图片视为一页；仅识别常规文字，公式、矩阵、复杂版面可能识别错误。拍照入口、识别结果人工校对和公式专项识别后续单独实现。图片需不超过 2500 万像素和 50MB，运行服务的电脑需要 RapidOCR 依赖。

## 浏览器验收

1. 后端代码有更新，需要在运行后端的 PowerShell 窗口按 `Ctrl+C`，再启动：

   ```powershell
   Set-Location -LiteralPath 'D:\我的文档\文档\ChatGPT\codex学习\RAG'
   Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
   .\scripts\start-c-demo.ps1
   ```

   前端保持运行。打开 `http://127.0.0.1:5173/` 并登录，选择自己的**私有练习知识库**；不要把测试图片上传到公开库。

2. 选择一张清晰、包含多行数学文字或题目的 PNG/JPG/JPEG 图片，加入上传队列并上传。不要使用模糊照片或仅有一个符号的图片；避免上传个人敏感信息。
3. 等待文档列表显示“已就绪”。处理过程会使用本机 CPU，较大图片可能需要一些时间。若 OCR 没识别到内容，系统会显示失败或内容不符合要求，不会假装成功入库。
4. 点击“预览正文”，检查 OCR 文字是否出现在切片中。再用图片中的一段清晰文字提问，检查问答是否能检索到引用片段。当前是模拟模型，回答正确性不作为验收标准。
5. 点击引用中的“查看对应正文”和“打开图片原文件”，确认能分别查看识别文字及原图。
6. 可选：同格式替换一张图片，确认资料编号和名称保留；无须替换任何重要资料，使用新建的练习资料即可。

## 常见错误与恢复

- 选择窗口看不到图片：确认扩展名是 PNG、JPG 或 JPEG；也可直接拖拽到上传区域。
- 状态为“处理失败”：查看错误是否提示缺少 RapidOCR 或当前 `OCR_ENGINE` 不是 `rapid`。不要在用户不知情时安装/升级全局包；先检查项目虚拟环境和本机配置。
- 状态为“内容不符合要求”：图片过模糊、文字太少、分辨率超限，或 OCR 未识别到可用字符。换一张清晰的练习图片重试。
- 文字可见但公式不准确：这是当前纯文字 OCR 的限制，后续任务再增加公式识别和人工校对。
- 原图无法打开：确认用户仍已登录且知识库没有撤销公开；原图接口只服务所有者或已公开库的登录读者。

## 实现说明

- 前端上传检查和文件选择器允许 PNG/JPG/JPEG。
- 后端检查扩展名与图片真实格式相符，限制像素数并应用 EXIF 方向，再用 RapidOCR。
- OCR 产物只有在识别成功后才进入已有文档入库流程。小图片允许短于普通文档的文字量，避免单道数学题因 50 字门槛被拒绝。
- 原图可通过受权限保护的 `/api/docs/{doc_id}/file` 接口 inline 查看；图片可走原有同格式替换和版本备份。

教师验证：前端 `npm run build` 成功；相关 Python 文件语法编译成功；`git diff --check` 通过；本机运行模式已确认 OCR 启用且为 rapid，后端和前端代理健康检查返回 200。未运行自动测试，图片端到端效果等待学生用浏览器验收。

## 审查修复补充

图片上传与新版本替换已共用文字门槛：PNG/JPG/JPEG 至少 5 个字符，普通文档仍至少 50 个字符。切片器对图片也允许短片段，避免通过前置校验后又被默认 20 字过滤；普通文档切片仍保持原规则。

新增 PNG/JPG/JPEG 回归测试：模拟 OCR 推理输出，实际验证短题上传、正文预览、替换、旧版备份和过短替换失败后的数据保留。连同原正文编辑、替换及切片测试共 34 项通过；该测试不代表真实 OCR 识别质量已验收。

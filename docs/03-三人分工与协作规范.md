# 03 · 三人分工与协作规范（v2.1）

## 1. 分工原则

按**数据流切段**，不按文件切：A 把资料变成可检索的块，B 把块变成可信的回答，C 把回答变成人愿意用的产品。
三段之间只有两份契约（`ChunkMetadata`、`OpenAPI`）。**契约稳定，内部自由。**
范围之外的活一律不做——包括"顺手加个头像""顺手做个相似题"。判据见 `06-范围基线.md` §1。

## 2. WBS（只列范围内任务）

### A · 知识工程（118h）

| # | 任务 | 阶段 | 产出 | 验收 |
|---|---|---|---|---|
| A1 | 语料采集 + 清洗脚本 | P0 | `knowledge/raw/*`、`scripts/clean.py` | **Gate 0 语料指标达标** |
| A2 | 多格式解析（md/docx/txt） | P1 | `services/parsing/*` | 统一输出 `Document{blocks[]}` |
| A3 | 结构化识别（知识点/例题/习题） | P1 | `services/parsing/segmenter.py` | 抽 50 段，识别准确率 ≥ 85% |
| A4 | 公式保护切片器 | P1 | `rag/splitter.py` | 1000 次随机切片 0 次截断公式（单测） |
| A5 | 切片长度三档实验 | P2 | 300/500/800 对比记录 | 给出 Recall@5 最高的那一档 |
| A6 | Embedding + 批量入库 + 去重 | P1 | `rag/embedder.py`、`rag/indexer.py` | 1000 chunk < 3min；重传不产生重复 |
| A7 | PDF 解析 + 噪声清洗 + 页码映射 | P2 | `services/parsing/pdf.py` | 页眉页脚去除率 > 95%；页码可回溯 |
| A8 | 无文本层拒收 | P2 | `status=rejected` 分支 | 扫描件返回明确文案，不入库 |
| A9 | 生命周期：删除/重建/增量/一致性 | P2 | `reindex` 接口 + `check_consistency.py` | 删除后 `where={"doc_id"}` 查不到残留 |
| A10 | 文档列表/状态/预览接口 | P2 | `api/doc.py` | 17 项接口里的 6 项 |

**A 的三个真难点（答辩要讲）**
1. 公式不被切断：占位符法（`$...$`、`$$...$$`、`\begin{}` → `@@MATH_i@@`），切完还原，比写复杂正则安全。
2. PDF 断行与排版：按 block 取，行尾无标点且下行非编号则合并。
3. chunk 粒度：太小丢上下文、太大稀释语义——用实验数据定，不拍脑袋。

### B · RAG 引擎（130h）

| # | 任务 | 阶段 | 产出 | 验收 |
|---|---|---|---|---|
| B1 | 大模型客户端封装 | P0 | `rag/llm.py` | 流式 + 重试 + token 统计 |
| B2 | 检索封装 + 纯向量 pipeline | P1 | `rag/retriever.py`、`pipeline.py` | 输入问题 → answer + citations |
| B3 | Prompt 体系（System + 3 套 Few-shot） | P1-P2 | `rag/prompt.py` | 方程/函数/证明各 10 题，人工合格率 > 80% |
| B4 | SSE 流式 + citation 事件 | P1 | `/chat/stream` | 事件序列符合 `01` §6 |
| B5 | SSE 事件模型 + 契约测试 | P0 | `schemas.py` + pytest | mock 文件逐帧反序列化通过 |
| B6 | 混合召回 + RRF | P2 | `rag/hybrid.py` | 消融：Recall@5 提升 ≥ 5pt |
| B7 | Rerank | P2 | `rag/reranker.py` | MRR 提升可测 |
| B8 | 拒答与置信度 | P2 | 阈值 + 兜底话术 | 20 个库外问题 ≥ 16 个明确说"未找到依据" |
| B9 | 多轮上下文（3 轮，不改写） | P2 | `rag/context.py` | 追问能承接上文；token 不超预算 |
| B10 | 评估集 80 题 + 消融 + 复现脚本 | P3 | `scripts/eval.py`、`eval/math_80.jsonl` | 指标出数且可复现 |
| B11 | 重复 query 缓存 | P3 | 内存 LRU | 重复问题 P95 < 300ms |

**B 的三个真难点**
1. 为什么要混合召回：题干含精确符号（BM25 命中率高），"求导"≈"导数计算"（向量补语义），RRF 免归一化。
2. 幻觉三层：检索门槛（不达标拒答）→ Prompt 强制引用 → 后处理校验 `[n]` 必须存在。
3. 评估方法论：从 chunk 反推出题（gold 天然存在），temperature=0，跑 3 次，抽 20 题双人判定报一致率。

**C 的三个真难点**
1. SSE 手写解析：`EventSource` 不支持 POST + JWT Header，必须 `fetch` + `ReadableStream` + `TextDecoder`。
2. 渲染性能：逐 token `setState` 会卡，buffer + `requestAnimationFrame` 批量 flush。
3. 公式顺序：先占位符保护 → 渲染 Markdown → 还原 KaTeX，否则 `_`、`*` 会打乱公式。

**交接自查（每次合并前）**
- [ ] 我的接口在 `/docs` 可见，字段名与 `01` 一致
- [ ] 有 docstring，别人能照着调
- [ ] 没改别人目录下的文件（契约文件除外）
- [ ] 新依赖写进 `requirements.txt` / `package.json`
- [ ] 新环境变量写进 `.env.example`
- [ ] 检索/删除类接口补了越权测试

## 4. Git 规范

```
main           ← 只接受来自 dev 的 PR，随时可部署
 └ dev         ← 集成分支，周五集成日合并
    ├ feat/a-pdf-parser
    ├ feat/b-hybrid-retrieval
    └ fix/c-sse-parse
```

- 分支：`<type>/<owner>-<subject>`，`type ∈ feat|fix|refactor|chore|docs`
- 提交：`feat(rag): 支持 BM25+向量 RRF 融合召回`
- PR：**按"可独立验证的功能"切**（不设行数上限）；跨人 review（A→B→C→A）；CI 绿才可合；改 `rag/` 必须附 eval 指标。
- 禁止：直接 push `main`；提交 `.env` / `data/` / `*.db` / 大语料。
- 每天下班前 push 到 feature 分支，未完成写 `WIP:` 前缀。

## 5. 代码与工程规范

| 项 | 规范 |
|---|---|
| Python | ruff + black（行宽 100）；public 函数必须类型注解；异常统一 `AppError(code, msg)` |
| TS/Vue | eslint + prettier；`<script setup lang="ts">`；API 调用集中在 `src/api/` |
| 日志 | 结构化 `extra={...}`；禁止 print |
| 配置 | 只走 `core/config.py`；禁止硬编码 key/路径 |
| 密钥 | `.env` 本地；`.env.example` 入库；上线用环境变量 |

## 6. 沟通与冲突

- 技术分歧：24 小时内用"1 页纸对比 + 小实验"定；谁提议谁举证；仍不一致由当周集成负责人拍板。
- 进度落后：**当天**在群里说 + 按 02 §10 的砍单顺序降级，不许默默延期。
- 被打断：可以随时拉人看 5 分钟代码，但不许直接改别人分支。
- 轮值：每周一人当集成负责人（A→B→C），负责周五合并、跑 smoke、更新进度表。

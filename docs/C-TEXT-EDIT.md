# TXT／Markdown 正文编辑

目标：修改服务器正文、自动更新检索索引，并验证失败时旧内容保留。前置条件：已登录，前后端运行，练习知识库内有一份已就绪的 UTF-8 TXT 或 Markdown。

## 浏览器跟练

1. 刷新 http://127.0.0.1:5173/ ，进入练习知识库。先选用自己创建的练习资料，不编辑重要原件。
2. 点击 TXT／MD 旁的“编辑正文”。预期看到上传文件的完整原始正文，保留 Markdown 和 LaTeX 标记；不是把预览片段拼回去。PDF／Word 没有此按钮。
3. 在末尾加入至少 60 字独有内容，例如函数导数的定义与一个例题。点击“备份并保存”，核对确认框中的文件名和影响，再确认。
4. 等待保存完成。预期编辑器关闭，提示正文与索引已更新。重新打开“预览正文”，应看到新增内容；片段数可能变化。再打开编辑器，新增内容应仍在。
5. 刷新页面，重新打开编辑器验证持久化；检查电脑上的原始练习文件没有被修改。

保存期间会生成新切片与向量，不是只修改显示文字。当前模拟服务仍不能用于验证真实数学解答质量。

## 独立练习：失败与取消

- 将正文临时改为“太短”，尝试保存。预期提示处理后正文至少需要 50 字符，服务器旧版仍保留；可点“重新读取”并确认丢弃本页修改。
- 修改一个字后点“关闭编辑”，在放弃修改确认框中先取消，编辑内容应保留；再次关闭并确认，服务器正文不变。
- 可选版本冲突测试：两个浏览器标签页打开同一份资料的编辑器，先在第一个标签页保存，再在第二个保存不同修改。第二个应提示版本已更新，不覆盖第一份。先复制第二个页面需要保留的文字，再重新读取、合并并保存。

## 限制与恢复

- 只支持 UTF-8 的 TXT／MD，每份最多 20 万字符；PDF、Word 和大文件后续通过文件新版本替换。
- 处理中或系统正在入库时返回 409，等待处理结束后重新读取。编辑器打开期间锁定知识库切换和文档上传删除，关闭后恢复。
- 保存超时或连接断开不等于服务器未保存。先复制本页草稿，再重新读取核对，不自动重复提交。
- 校验与向量生成先完成，再替换正文与索引。普通写入失败会尝试恢复旧文件、片段和向量；相关故障已用隔离测试验证。
- 每次实际更新前，旧文件与索引快照保存在服务器上传目录的 `.versions/<文档ID>/<版本目录>/`。本机演示对应 `.tmp/c-demo/uploads/.versions/`。备份不通过公共 URL 暴露。需要恢复旧版时，可读取备份 TXT／MD，复制所需旧正文到当前编辑器，经确认后保存为新版本，不直接覆盖数据库或向量文件。
- 删除文档时确认框会说明同时清理该文档的旧版备份。保留电脑原件，勿把版本备份当作独立长期备份。
- 当前是单进程协调与故障补偿，不是跨 SQLite、文件和向量库的分布式事务。断电或进程强制终止时可能需要用保留的快照人工恢复，不能保证自动恢复。
- 修改后原有对话文本不变；旧引用片段 ID 可能失效。用新对话检索新版本。

## Codex 实操

尝试解释三个成功标准：为什么编辑时要读原始正文？为什么保存时要携带版本号？为什么向量生成失败后还应能查看旧正文？

接口新增：GET /api/docs/{id}/text 与 PUT /api/docs/{id}/text；后者需要登录、CSRF、content 和读取时的 version。静态 OpenAPI 已同步。

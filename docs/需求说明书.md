---

## 1. 项目目标

把考研数学一相关的教材、讲义、习题资料，转成**可检索、可引用、可删除**的知识块（chunk），
并以 6 个接口交给 B（问答）与 C（平台）使用。

A 的成功标准只有四条：**切得对、存得住、删得干净、接口稳定**。检索与生成的质量归 B。

## 2. 范围

### 2.1 纳入范围

| 编号 | 能力 | 说明 |
|---|---|---|
| S1 | 多格式文档解析 | PDF（文本层）、扫描版 PDF、DOCX、Markdown、TXT |
| S2 | 扫描件 OCR | 图片文字识别，输出可检索文本 |
| S3 | 数学公式 LaTeX 化 | 识别公式并转成 `$...$` / `$$...$$` |
| S4 | 结构化信息提取 | 正文、例题、习题、定理/定义、题注（图/表标题） |
| S5 | 面向数学的切片 | 公式不被切断、例题不被拆散、按知识点组织 |
| S6 | 向量化与入库 | 文本 → 向量 → 关系库 + 向量库，带 ChunkMetadata |
| S7 | 文档生命周期 | 上传、进度、预览、删除、重建索引、同名覆盖、内容去重 |
| S8 | 对外接口 | 6 个 `/api/docs/*` 接口，统一响应与错误码 |
| S9 | 离线工具 | 语料抓取、OCR 预处理、体检、重建、一致性对账 |

### 2.2 不纳入范围

| 不做 | 归属 | 说明 |
|---|---|---|
| 检索、融合、Rerank、Prompt、生成、SSE | B | B 读 A 写入的 chunk 与向量 |
| 登录鉴权、知识库 CRUD、前端、部署 | C | A 只依赖 `user_id` / `kb_id` |
| 拍照识题入口（前端裁切上传） | C | A 只提供 OCR 能力，不做交互 |
| 自动打标签、相似题 | 范围外 | 不服务四条验收指标 |
| 模型微调、多模态生成 | 范围外 | 成本高、与可溯源目标正交 |

## 3. 功能需求与验收标准

状态标记：✅ 已实现并验证 ｜ ⚠️ 已实现但有限制 ｜ ⬜ 未验证

### FR-1 多格式解析

| 项 | 内容 |
|---|---|
| 输入 | `pdf` / `docx` / `md` / `txt`，单文件 ≤ 50MB |
| 处理 | 统一输出 `[(页码, 文本)]`；清洗页码行、页眉页脚、中文硬换行 |
| 验收 | 4 种格式均能入库并生成 chunk；`pytest` 覆盖 md 全链路 |
| 状态 | ✅（md 全链路已验证；docx/pdf 走同一接口，缺真实样本回归） |

### FR-2 扫描件 OCR

| 项 | 内容 |
|---|---|
| 触发 | PDF 抽样每页有效字符 < 50 且 `OCR_ENABLE=true` |
| 处理 | 页面渲染 @200dpi → rapidocr 识别 → 同行合并 → 页眉剥离 |
| 输出 | 每页文本，页码保留，供后续结构化 |
| 性能 | ≤ 5s/页（CPU，单线程）；884 页约 45–75 分钟 |
| 验收 | 扫描件不再被拒收；OCR 后每页平均字符 ≥ 20；任务状态出现 `stage=ocr` |
| 状态 | ✅ 30 页小样完成（6 本×5 页，153 秒）；密度 170 汉字/页、召回约 50%（密集页），见 `docs/OCR小样报告.md`；全量未跑 |

### FR-3 公式转 LaTeX

| 项 | 内容 |
|---|---|
| 独立公式行 | 无中文、符号密集的整行 → `pix2tex` 转 `$$...$$` |
| 行内公式 | 夹在中文句子中的公式 → **保留 OCR 原文**，不做强行转换 |
| 兜底 | 未装公式模型时保留原文并记录告警，禁止伪造 LaTeX |
| 验收 | 独立公式行 LaTeX 语法合法（KaTeX 可渲染）；行内公式作为已知限制记录 |
| 状态 | ⚠️ 独立公式行成功；行内公式与矩阵/行列式仍失真（30 页小样：24 块公式，矩阵出现垃圾 LaTeX），详见 `docs/OCR小样报告.md` |

### FR-4 结构化信息提取

| 类型 | 判定规则 | 状态 |
|---|---|---|
| 正文 `concept` | 默认类型 | ✅ |
| 例题 `example` | 行首 `例 N` / `例题` / `解：` / `证明：` | ✅ |
| 习题 `exercise` | 行首 `习题` / `练习`（兼容 `## 习题` 标题） | ✅ |
| 定理定义 `theory` | 行首 `定理` / `定义` / `性质` / `推论` | ✅ |
| 题注 `caption` | 行首 `图 N-N` / `表 N-N` | ✅（v1.1 新增） |
| 验收 | 抽 50 个块人工核对，类型准确率 ≥ 85% | ⬜ 待用真实语料抽检 |

**例题完整性**：`例 N` 连同后续 `解 / 证明 / 分析 / 答案 / 点评` 合并为同一 chunk，
中间夹的纯公式段也并回，避免"题干与解答被拆开"。

### FR-5 切片

| 项 | 规格 | 状态 |
|---|---|---|
| 目标长度 | 600 token（中文约 960 字） | ✅ |
| 硬上限 | 750 token（×1.25） | ✅ |
| 公式保护 | 占位符法，切点不落在 `$...$` / `$$...$$` / `\begin{}` 内 | ✅ |
| 公式膨胀 | 还原后超限 → 按行重切；单行超长公式保持原子 | ✅ |
| 标题归属 | 短标题作为下一段前缀，不单独成 chunk | ✅ |
| overlap | 80–120 token，仅被迫切断时使用 | ✅ |

### FR-6 向量化与入库

| 项 | 内容 | 状态 |
|---|---|---|
| Embedding | `dev` 哈希向量（链路验证）/ `api` bge-m3（评估必须） | ✅ |
| 向量库 | 本地文件实现；`VECTOR_BACKEND=chroma` 可切 | ✅ |
| Metadata | 10 个字段（见 `A-接口与边界.md` §4），`page` 为空时省略 | ✅ |
| 一致性 | 写向量失败 → 回滚关系库记录，禁止半成功 | ✅ |

### FR-7 文档生命周期

| 能力 | 规则 | 状态 |
|---|---|---|
| 去重 | 同库同内容（sha256）→ `1005` | ✅ |
| 同名覆盖 | `overwrite=true` → 删旧（向量→chunk→文件）再建 | ✅ |
| 删除 | 删后 `where={"doc_id"}` 必须查不到残留 | ✅ |
| 重建 | `reindex` 幂等，chunk 数不变 | ✅ |
| 状态机 | `pending → parsing →(ocr)→ embedding → ready`，异常 `failed` / `rejected` | ✅ |

6 个接口与错误码见 `docs/A-接口与边界.md` §3；统一响应 `{code,message,data,request_id}`。
状态：✅ 全部通过集成测试（含越权 403、重复 1005、非法类型 2002）。

## 4. 非功能需求

| 类别 | 要求 | 现状 |
|---|---|---|
| 性能 | OCR ≤ 5s/页；入库 1000 chunk < 3 分钟（dev 向量） | OCR 3–5s/页 ✅；入库未压测 |
| 并发 | 单进程、单写者，入库任务串行；并发上传排队 | ✅ 已实现锁 |
| 可靠性 | 失败必须可见（`error_msg`），禁止静默成功 | ✅ |
| 可运维 | 任务进度可查、日志结构化、脚本可独立运行 | ✅ |
| 合规 | 原始语料与 OCR 产物不入公开仓库；来源与许可记录在 manifest | ✅ |

## 5. 数据需求

| 项 | 要求 |
|---|---|
| 格式 | PDF（文本层或扫描件）、DOCX、MD、TXT |
| 规模 | Gate 0：≥ 5 万字、≥ 30 处例题；单库建议 ≤ 2000 chunk |
| 组织 | `knowledge/raw/<科目>/`，命名 `<来源>-<书名>-<册次>` |
| 版权 | 仅使用有权限的资料；商业教辅仅本地个人使用，不提交仓库、不整页演示 |
| 现状 | 6 本考研 PDF（884 页）全为扫描件，已可 OCR；尚未全量转换入库 |

## 6. 约束与假设

1. 只有 CPU，无 GPU：OCR 与公式识别都走 CPU 推理，速度按 3–5s/页估算。
2. 无商业 OCR key：公式走本地 pix2tex；Mathpix 兼容接口已预留（`OCR_FORMULA=api`）。
3. 网络受限：pip / GitHub 需绕代理（见 README 排障）；模型权重首次使用需联网下载。
4. 团队三人共用仓库：A 不改 B/C 模块，接口只增不改。
